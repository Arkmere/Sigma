- Ticket 12 — hardening pass: a focused adversarial audit of Tickets 8–11, using both an automated security review and direct manual verification against a real browser (every finding reproduced and re-verified in Chromium via Playwright, not just reasoned about). Found and fixed four issues: (1) a hash-router bug where the async `hashchange` event fired by `syncHash()` silently wiped success notices from actions that also changed route — "Reset all data" from a non-Profiles screen, and switching the acting adult while on a Family sub-stage, never showed their confirmation; (2) `importFitCard` only checked that the imported payload's record collections were arrays, not that their elements were well-formed, so a malformed record from a decrypted (fully sender-controlled) import file could reach local storage and then fail the stricter reload-time validator, corrupting the whole local dataset and forcing a destructive full reset; (3)+(4) two stored-XSS gaps that followed directly from (2) — an imported measurement's `originalValue` and the notice banner's message text were both being rendered without the app's usual HTML-escaping, so an imported fit card with malicious display strings could execute script on import. Fixed by reusing `migrations.ts`'s existing (already correct, already tested) record validators inside the live import path instead of only at reload, and by escaping both render sites. Confirmed the fix by actually attempting both attacks — a malformed value type, and valid-shaped strings containing `<script>`/`onerror=` — against a real running instance: both are now neutralized (import rejected or content shown as literal escaped text; no script execution, no dialog). One design trade-off is documented rather than changed: fit-card reconciliation is keyed on a sender-supplied ID with no cryptographic binding to that file's passphrase, an inherent property of the passphrase-only exchange model rather than an oversight. 5 new tests. ## Current Repository State

- Framework: dependency-free TypeScript static application.
- Domain: `src/domain` owns the schema, taxonomy, history rules and record service.
- Persistence: `src/data/repository.ts` owns explicit load states; `src/data/migrations.ts` validates and dispatches schema versions.
- UI: `src/app/app.ts` orchestrates state/events while focused modules under `src/app/ui` render screens and translate forms.
- Data scope: schema-7 local records, optional canonical identifiers, correction metadata, Families, memberships, adult connections, sharing grants and imported fit cards.
- Source scope: manual entry is active; future source types are schema vocabulary only.
- Privacy: no account, cloud, telemetry, analytics, advertising, external service or permission request.
- Testing: Node built-in test runner with domain, reload/persistence and lightweight DOM interaction coverage.
- Linting: no real lint command exists yet.

## Known Limitations

- localStorage is synchronous, browser-scoped, capacity-limited and not encrypted by Sigma.
- JSON backup download is export-only; import/restore is not implemented.
- Physical values support append-only history and non-destructive correction, with true deletion also available (a value, a whole record, or a whole profile) since Ticket 9.
- Standard-size and brand-fit records can be edited, but those edits do not yet create a separate audit history.
- The expanded taxonomy remains a starter catalogue rather than exhaustive; custom labels remain available.
- Corrupt/unsupported storage has no recovery, raw export, import or restore path; only confirmed reset is available.
- Tests use a lightweight DOM harness, not a full browser or native mobile runtime.
- The development server builds once and does not watch files.
- No real linter is configured.
- Browser visual verification is limited to the viewports and themes recorded below; there has been no formal accessibility or WCAG audit.
- The public ISO catalogue does not expose footwear table contents, so only the specification-supplied adult row is encoded; other rows and child conversions return no result.
- Clothing, hat, glove, regional ring and specialist/equipment conversions are deliberately unsupported rather than guessed.
- Consent is a same-device simulation, not authenticated remote consent; there is no cloud sync, authenticated accounts, payments, external integration or production child-law policy. Local accounts have no password or security of any kind — anyone with the device can select or create any account, including the Admin test identity. Cross-device sharing (Ticket 10) is a manually exchanged, passphrase-encrypted export file, not a live sync or account relationship — a lost passphrase makes that export permanently unrecoverable, and there is no key-exchange protocol.

## Important Decisions Made

- LocalStorage is isolated behind `DataRepository`, allowing a later IndexedDB adapter without coupling UI/domain code to storage calls.
- Measurement values are immutable child entries; current value is derived rather than overwriting history.
- `originalValue` and `originalUnit` remain explicit even before Ticket 3 introduces converted display values.
- Every record is tied to one profile and marked private; visibility has no sharing effect in Ticket 2.
- Structured JSON export is available, while import is deferred to avoid unsafe restore semantics.
- Ticket 2 adds no recommendation, conversion, Family, permission, cloud or payment behaviour.
- Invalid JSON, invalid version-1 structures and broken profile references are surfaced as corrupt without modifying raw storage.
- Unknown schema versions are surfaced as unsupported and routed through a dedicated migration boundary.
- Unsafe repository states are read-only until reset so creating a profile cannot overwrite unreadable personal data.
